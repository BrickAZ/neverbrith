# `isaac-collectibles` 设计

## 目标

为下载技能包的用户提供一个通用入口，用于新增、修复和审查**被动 Collectible**。它让 AI 在未知 Mod 项目中先发现真实注册、实现和测试位置，再安全处理被动道具的注册、持有判定、基础效果与生命周期。

此 skill 不依赖 neverbrith、参考 Mod、绝对路径或第三方库。

## 触发范围

当请求涉及被动道具、Collectible、`items.xml`、`Isaac.GetItemIdByName`、`player:HasCollectible`、道具拿到后生效、被动属性、道具效果失效、已有被动道具 Bug 或被动道具审查时触发。

主动道具不在范围内，改由 `isaac-active-item-mechanics` 负责。

## 工作流程

1. 使用 `isaac-mod-context` 发现真实的 Mod 对象、Lua 入口/模块、`items*.xml`、语言变体、已有被动道具、依赖声明和测试入口。
2. 读取最接近的现有被动道具；没有时使用本 skill 的自包含官方 API 参考，不猜测项目布局或引入外部库。
3. 先写清道具契约：注册名/ID、用户已决定的效果、持有者、叠加规则、何时生效、何时失效、未知设计项。
4. 把基础实现限定为以下一种或组合的明确责任：
   - Cache 属性修改；
   - 受拥有者过滤的事件效果；
   - 对本道具自有状态、视觉或生成物的管理。
5. 将跨域实现交给现有技能：主动壳层→`isaac-active-item-mechanics`；回调签名/返回→`isaac-callback-contracts`；投射物→`isaac-projectile-combat`；使魔→`isaac-familiars`；实体注册→`isaac-entities`；状态/保存→`isaac-state-lifecycle`；重掷与失去道具后的对账→`isaac-reroll-removal-contracts`（可用时）；经济→`isaac-item-economy`。
6. 对已有道具修复或审查时，先证明注册、持有判定、回调过滤和生命周期，再修改逻辑；不得用全局清理或 player 0 假设掩盖归属问题。
7. 输出静态检查、自动化行为测试和仍需游戏内验证的区别。

## 核心规则

- 只处理被动 Collectible 的基础生命周期，不替代主动道具、饰品、卡牌、角色、Boss 或房间技能。
- 不把道具 ID、数值、品质、道具池、标签、视觉设计或叠加语义擅自补全；未给出的设计项为 `TBD`。
- 以真实拥有者为准，支持多角色/合作模式；不把 `Isaac.GetPlayer(0)` 或全局“任意玩家拥有”当作默认所有权。
- 只创建、移除或重建该道具能证明归属的状态、实体、视觉与缓存贡献。
- 缓存效果必须有发现到的刷新路径；不得逐帧永久加减属性。
- 参考 Mod 只能用于维护者离线校准，不能出现在用户运行时工作流或成为依赖。

## 必需输出

```markdown
## Collectible Contract

- 已发现的注册与实现位置：
- 被动道具 ID/名称：
- 用户锁定的效果：
- 未决定项（TBD）：
- 持有者与副本/合作模式规则：
- 效果责任（Cache / 事件 / 自有状态）：
- 回调、过滤与返回规则：
- 失去、重掷、死亡、换房、续关和读档边界：
- 调用的协作技能：
- 静态检查、自动化测试与游戏内检查：
```

## 验证

skill 的 eval 至少覆盖：

1. 新增一个纯 Cache 被动道具，且项目布局未知。
2. 修复一个持有判定或合作模式归属错误的被动道具。
3. 一个被动道具生成自有投射物/使魔，正确路由到兄弟技能而不重复实现。
4. 一个用户未指定数值、叠加或失效规则的请求，保持这些字段为 `TBD`。
5. 一个没有第三方库的项目，验证 skill 不要求 EID、CuerLib、StageAPI、MCM 或 REPENTOGON。

## 完成标准

- skill 的说明能稳定触发于“被动道具新增、修复、审查”。
- 用户可在没有 neverbrith 或任何参考 Mod 的项目中使用它。
- 每个输出都能区分已发现项目事实、用户锁定设计、`TBD` 和需要游戏内验证的行为。
- 它不会吞并现有主动道具、投射物、使魔、状态或经济技能的职责。
