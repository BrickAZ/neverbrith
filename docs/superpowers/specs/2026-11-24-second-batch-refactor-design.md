## 道具与模块边界

| 道具 | 建议路径 | 迁移内容与重点 |
| --- | --- | --- |
| 春药 | chunyao.lua | 扣充能、伤害代价、90 逻辑帧的可叠加效果、属性和颜色/追踪标记；先补重复使用与逐份到期测试 |
| 美工刀 | utility_knife.lua | 伤害加成、获得时碎心、库存差额核对、旧 utilityKnife 数据；从与避孕套/椰子混排的代码中完整抽出 |
| 虚空针尖 | needletick.lua | 幸运触发、原泪弹变体与表现、碰撞结算、目标过滤和同一泪弹去重 |
| 绝育证明 | sterilization_certificate.lua | 房间初始实体记录、新增召唤物识别、召唤者反伤及去重；保留无人持有时不扫描房间的路径 |
| 剪碎的塔罗 | shredded_tarot.lua | 卡牌筛选与转换、奖励上限、主动槽消耗、持有幸运和未使用时跨层移除 |
| 血颅蛊 | blood_skull_gu.lua | 跟班来源查询、牺牲来源道具、属性成长、掉落与无合法跟班时的反噬；拥有反噬重入深度 |
| 未剪断的脐带 | uncut_cord.lua | 延迟伤害债务、第二次受伤结算、战斗房计数、反馈和重入保护 |
| 空摇篮 | empty_cradle.lua | 伤害类别、每层资格、待结算房间奖励、降级与黑心伤害加成，以及血颅蛊代价排除 |

方案编写时，这些内容均由[main.lua](../../../main.lua)拥有。美工刀实现分散在 GetUtilityKnifeData、EvaluateUtilityKnife、GrantUtilityKnifeBrokenHeart、TrackUtilityKnifeCopies 和末段注册处，迁移必须完整覆盖，不能仅搬属性函数。

## 三件联动与安装顺序

当前 bloodSkullGuBacklashDepth 在主文件上部声明，由血颅蛊在 TakeDamage 调用期间增减，脐带和空摇篮读取。它不是一般伤害分类服务。

迁移后由血颅蛊实例私有持有该深度，导出无副作用的 IsBacklashActive() 查询。入口向脐带、空摇篮显式传入这一查询，不暴露计数、不允许消费者修改，不通过 TestAPI 协作，也不新增全项目伤害总调度器。

脐带原回调登记早于血颅蛊，必须保持。装配可以传入延迟调用的查询闭包，实例在原血颅蛊位置安装后赋值；查询只在全部装配完成后的伤害事件中调用。实施时用真实入口测试确认构造阶段不调用该查询、三件只安装一次，以及伤害顺序未变。必要时采用分开的构造/注册阶段，但不改变原登记穿插顺序。

血颅蛊使用 pcall 包围反噬扣血，成功或异常后都恢复深度；继续保留这一合同及原有日志。查询不取随机数、不读写存档、不扣血。

美工刀的各回调原来分散在末段登记，实施时可在原位置登记模块导出的处理器。不要为了一次 Install 调用方便而把这些回调聚集到新的统一位置。

“继续时不清空运行时表”不等同“跨进程继续能够恢复”。本批不把尚无落盘机制的状态改成持久状态，也不新增沙漏参与；如实施核对发现原实现与已确认设计冲突，记录为独立问题，不以重构名义决定新玩法。

每步可单独检查；回退到第二批开始时的工作区副本，保留第一批成果及其他任务改动。不提交、推送、发布或升级原生运行时。

## 验证计划

已有专项测试：needletick、sterilization_certificate、shredded_tarot、blood_skull_gu、uncut_cord、empty_cradle 的行为测试，以及 condom_utility_knife_behavior_test 中的美工刀断言。测试夹具已通过 repentogon_test_fixture 支持 scripts 模块加载；仍须用迁移后的真实入口确认没有变成空模块或只测旧代码。

新增或补强：

- 春药：低充能、单次和重复使用、90 帧边界、不同时间取得的效果分别到期、多人隔离、与芜湖/风油精的属性及泪弹标记组合。记录当前行为而不静默修正设计。
- 美工刀：实际增加、重复回调、持续核对、移除再获得、继续旧计数及新局；基线若已有问题，单独报告，不冒充本批退化。
- 联动：血颅蛊反噬不被脐带延期、不消耗空摇篮奖励资格；反噬正常结束或抛错后，普通伤害仍走原路径；既有脐带债务不在反噬期间意外结算。
- 伤害组合：三件与八音盒及原伤害链的顺序、取消返回值和重入行为，沿用现有真实入口登记和伤害调度测试。
- 实体/随机：针尖碰撞与死亡路径最多结算一次，原免疫目标保持；绝育证明不误伤初始敌人/友方/掉落且多人不重复；塔罗牌数边界、排除符文和魂石、主动槽及跨层消耗；血颅蛊来源道具移除后不由缓存重新生成。
- 完整入口：每个模块安装一次，原回调事件/顺序/过滤/优先级保持，模块缺失和重复安装反例确实失败，既有公开方法仍可调用。

实施后的检查入口为 tools/check-neverbrith.ps1 的 LuaAll，加受影响的检查器/导航自测及资源哈希核对。原生场景覆盖本批的计时、碎心一次性结算、泪弹命中、召唤物拦截、卡牌转换、跟班牺牲和三件伤害联动；用同场景比较迁移前后并恢复测试设置/存档。只重做受本批影响的检查，不将第一批通过数当作新证据。
