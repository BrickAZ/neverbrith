# 阴的诅咒：爆炸免疫判定原生接口设计

日期：2026-10-02。状态：**方案一规格已确认，候选已实现**。用户于本日以“开始吧”确认书面规格并要求推进，具体任务见[实施计划](../plans/2026-10-02-yins-curse-explosion-immunity-interface.md)，当前证据见[候选交付记录](../../../reports/yins-curse/native-interface/2026-10-02/delivery.md)。新增接口已实现为本地候选，当前安装版仍没有本接口；尚未替换安装文件或进行实机验收。

## 1. 设计依据与范围

用户要求精确封锁爆炸免疫，并在三个候选方案中选择“方案1”。最终路线是在原生引擎的爆炸免疫决策点新增专用接口，Lua 仅提供诅咒条件。各免爆出口的局部原生 hook 是接口内部接入方式，不另采用只服务本机固定地址的私人补丁路线；本轮也不建立通用防护来源登记系统。

既有规则见[黑蜡烛合同](../../../reports/yins-curse/2026-09-16-black-candle-contract.md)，原生依据见[本机接口调查](../../../reports/batch-completion/2026-10-02-yin-explosion-interface.md)。现有实现为 [yins_curse.lua](../../../yins_curse.lua)。保留本局诅咒激活、品质 4 结算、其他道具效果、资源与已确认存档语义。

目标：诅咒已激活且实际受伤玩家没有黑蜡烛时，撤销各个来源的爆炸免疫，让同一次原始伤害继续原生流程；其他保护和该来源的非免爆能力保持原行为。

| 诅咒已激活后的受伤玩家状态 | 结果 |
| --- | --- |
| 无黑蜡烛、无免爆来源 | 原生伤害流程 |
| 无黑蜡烛、有免爆来源 | 撤销各个来源的爆炸免疫，继续原生伤害流程 |
| 有黑蜡烛、无免爆来源 | 原生伤害流程；黑蜡烛不新增免疫 |
| 有黑蜡烛、有免爆来源 | 原来源正常提供免疫及其他能力 |

诅咒未激活时，接口监听器不改变任何免疫。伤害仍可能被圣光斗篷、通用无敌帧或其他非爆炸专属保护挡下；“封锁免爆”不等于强制扣血。

## 2. 机制契约

- 玩家承诺：只让爆炸专属免疫失效，相关道具的其他功能仍可用。
- 内容归属：既有 Yin's Curse，现有本局激活状态加实际受伤玩家当前的黑蜡烛状态。
- 触发事件：原生发现某来源满足爆炸免疫资格，准备据此阻止当前玩家伤害。
- 条件：诅咒已激活、目标是实际受伤玩家、当前原因明确为爆炸免疫、该玩家无黑蜡烛。
- 排除：纯火焰免疫、护盾、通用无敌、来源不明的第三方取消、未发生的命中，以及其他玩家的状态。
- 立即结果：只撤销当前来源的爆炸免疫资格；既不取消当前伤害，也不直接操作健康值。
- 持续状态：读取现有诅咒存档；黑蜡烛每次判定实时读取，不建立全局玩家零缓存。
- 重入：不调用第二次 TakeDamage，不修改收藏品持有量；每次嵌套伤害拥有独立原生调用上下文。
- 结束/中断：黑蜡烛实时改变本次判定；新局、续局、复活和现有状态回退按已有确认语义重建，不保存原生指针或跨调用防护开关。
- 失败：无接口或不支持构建时明确报告该功能未启用；回调异常保留该来源原免疫并诊断，不能强制放行全部保护。
- 玩法载体：原生免疫决策接口与既有 Lua 诅咒条件。
- 音画载体：沿用原游戏反馈；不新增装饰性效果代替机制。成功免疫才可播放对应成功免疫反馈，非免爆副效果保留原条件。
- 兼容边界：原生审计覆盖的爆炸免疫出口；第三方独立返回 false 取消伤害的行为没有可识别原因，不能一律撤销。
- 原生复用：保留同一次原始 TakeDamage 的护盾、冷却、伤害修改、健康和死亡/复活流程；不复制这些系统。
- 隔离证明：未激活诅咒/有黑蜡烛/无订阅者情况下与原生行为对照一致；只在免爆资格处改变分支。
- 用户玩法待定项：无。实现路线已选定。下面未核实项为技术发现任务。

## 3. 接口契约

以下名称为本设计新增的接口，不能在当前安装版中当作已有 API 使用。

回调符号：`ModCallbacks.MC_PRE_PLAYER_EXPLOSION_IMMUNITY`。

完整 Lua 监听器签名：`handler(mod, player, hit, immunity)`。首个参数为隐式 mod。第一版不提供注册过滤参数，监听器通过 immunity 身份判断；避免将来源类型过滤误用成受伤玩家过滤。

| 参数 | 内容与限制 |
| --- | --- |
| player | 当前原生 TakeDamage 的实际玩家，仅本次调用有效 |
| hit | 原生调用上下文的值快照：`callId`、`damage`、`flags`、`source`、`countdown`；不接受监听器改写作为伤害修改 |
| immunity | 来源快照：`reason` 固定为 `EXPLOSION_IMMUNITY`、`sourceKey` 为稳定原生来源标识、可选 `collectibleId`、决策位置 `siteKey` |

hit/source/player 是短生命周期引用或值，不得保存到 JSON。快照字段变化不会反写引擎。传入快照为当前原生决策点的信息，监听器不能通过这个接口重写 damage/flags/source/countdown。

返回值：

| 返回 | 精确含义 |
| --- | --- |
| nil | 不干预当前来源的免爆资格 |
| true | 不否决当前来源；不赋予原本没有的免疫，也不能覆盖前面监听器的否决 |
| false | 否决当前来源的爆炸免疫资格，继续同一次伤害流程 |
| 其他类型/异常 | 忽略本监听器结果，保留已累积的有效否决，输出诊断 |

新接口的 false 与现有伤害回调的 false 含义不同，文档及测试必须显式说明。分派链沿用原优先级/同优先级注册顺序；所有适用监听器执行完，任一有效 false 保持否决，后置 nil/true/异常不能撤销它。最终结果只用于该免疫来源，不直接作为 TakeDamage 的返回值。

阴的诅咒监听器只在第 2 节条件成立时返回 false，其他情况返回 nil。监听器不按“两件道具 ID”白名单决定封锁，原生适配层负责准确分类所有被审计的免爆来源。

回调数字编号须在固定的原生源码版本中核对枚举、位图和分派注册后分配，不能凭本规格猜一个空闲数字。能力查询接口拟为 `Isaac.GetPlayerExplosionImmunityAPIVersion()`，完整第一版返回 1；单有回调枚举或 REPENTOGON 版本字符串不能证明能力完整。不得在仅接入两件来源的中间构建中对外宣称“所有原版来源已支持”。

## 4. 原生接入与副效果保留

先建立原生免爆出口清单，每条记录来源、进入条件、所有提前返回、非免爆副效果、寄存器/栈状态、继续执行位置，以及伤害回调相对顺序。不能假设引擎已有公共免疫函数。

已发现的 Pyromaniac/Host Hat 是清单起点：

- Pyromaniac：火焰判定与爆炸判定分开。免爆分支存在多个提前退出位置，必须覆盖满血/缺血等路径；不能只修改末尾退出。保留爆炸治疗等副效果的原条件与原生相对顺序，随后根据新接口决定是否免爆退出或继续伤害。不整段跳过纵火狂处理。
- Host Hat：爆炸免伤决策与其他投射物阻挡决策分开。拒绝免爆只改变前者，非爆炸投射物阻挡仍走原实现。与成功免疫直接绑定的反馈不能在免疫被否决时伪装成功。
- 多免爆来源：第一个来源被否决后还需检查其他来源，不能直接跳到扣血；所有免爆来源都可被阴的诅咒否决，保留非免爆保护。
- 混合标志：damage 包含爆炸和火焰等多个标志时，按实际原生保护原因分类。纯火焰/通用防护不能因出现爆炸标志被一并否决；此类命中仍可能被保留的其他防护挡下。

原始 damage/flags/source/countdown 不变。原普通伤害回调和既有 Mod 返回链在原流程所在位置继续执行；其 false 取消仍有效。单次伤害相关副效果不能因多个免爆出口而重复执行。原生适配通过特征与构建核对加载，不将本机绝对地址视为通用地址。

## 5. 加载、存档与缺失能力

原生层负责接口、来源适配和分派，Lua 层在现有 yins_curse.lua 中查询保存状态与黑蜡烛。共享存档根、`yinCurseActive`、`q4Mode`、`firstQ4Resolved` 沿用现有定义；不改变首个品质 4 分支的锁定时点。

加载时核验真实原生版本、接口能力版本、必要注册是否存在及完整来源覆盖。缺失时仅将这项精确封锁记为未启用并给出明确提示，不能注册一个空回调假装完成，也不能用取消伤害、整件禁用或第二次伤害代替。已有模组能力按当前依赖规则继续处理。

原生调用栈状态不持久化；监听器卸载后无需恢复物品、健康或临时封锁，因为没有修改这些状态。开发调试日志记录 callId、玩家、来源、siteKey、原生免疫资格、各监听器结果与最终决定，正常游戏不持续输出逐命中日志。

## 6. 验收矩阵

| 检查 | 必须证明 |
| --- | --- |
| 四种黑蜡烛/防爆组合 | 第 1 节结果全部成立；黑蜡烛单独不免爆 |
| 诅咒未激活/无订阅者 | 原生行为、结果、副效果与原构建一致 |
| 纵火狂满血/缺血 | 每条免爆退出均可否决；治疗条件/次数/顺序保留，记录治疗与伤害分开，不能只观察最终血量 |
| 火焰/混合标志 | 只否决明确爆炸免疫，保留其他保护原因 |
| 宿主帽 | 爆炸免疫可否决；普通投射物阻挡保持原行为 |
| 多个免爆来源同时存在 | 各来源均经过判定，没有漏过第二个来源 |
| 圣光斗篷/通用无敌帧 | 保留原生保护、消耗和接触节奏，不强迫扣血 |
| 普通伤害回调取消/修改 | 已有返回链继续生效，原始来源不丢失 |
| 新接口多监听器 | false 后接 true/nil/异常不能恢复免爆；前后优先级和过滤按契约 |
| 合作/双角色/嵌套伤害 | 按实际目标和独立 callId 判定，不共享临时全局开关 |
| 黑蜡烛取得/失去 | 下一次真实判定使用当前玩家状态；不改品质 4 已锁定分支 |
| 致死/复活/续局/状态回退 | 原生健康与生命周期一致，诅咒按已确认保存状态恢复，无第二次伤害 |
| 不支持构建/缺失接口/卸载 | 不错误跳转，不留下物品/健康修改；明确未启用 |

证据分层：源码/接口检查 → 固定构建的原生编译与分派验证 → 真实游戏伤害日志及画面。模拟 Lua 测试不能证明原生出口和副效果，编译成功也不能证明实机通过。最终必须记录原生源码 commit、补丁版本、DLL 与游戏 SHA256、启用 Mod、测试种子和玩家。
