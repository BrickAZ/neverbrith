# RingoTsuga 官方苹果人格三挂饰重画设计

## 目标

在不改动现有 Costume 接入合同的前提下，重画 RingoTsuga 的三张透明硬像素图集，使游戏内第一眼读作 Ringo 的官方苹果吉祥物，第二眼才读作《以撒的结合》中的角色适配。

本次保留三件互相独立的 Null Costume：

1. `head4`：苹果外壳、果梗与叶片；
2. `head2`：苹果内脸、巨大奶油色眼睛、瞳孔、嘴和极少量泪痕；
3. `body0`：浅灰白上衣与小型深灰肢体。

不回到完整玩家皮肤路线，不覆盖原版玩家图集，也不改变已经工作的 ANM2、Costume ID、优先级、Lua 槽位或生命周期逻辑。

## 已批准方向与路线取舍

### 采用：官方苹果吉祥物优先

- 暖珊瑚红苹果头，而不是正圆红色头盔。
- 苹果顶部有明显凹口、短棕色果梗和一片宽绿叶。
- 两只奶油色大眼占脸部主要面积，使用小而略微错位的深色瞳孔。
- 嘴很小；青色只保留为少量《以撒》泪痕，不再作为眼睛主体。
- 身体穿浅灰白上衣，配小型深灰手脚。
- 轮廓使用深棕灰，保持一像素为主且不使用纯黑统一粗描边。

### 未采用：以撒脸套进苹果壳

该方案能保留原版以撒辨识度，但会让苹果更像头饰而不是 Ringo 本人，与“苹果人格头”的选择冲突。

### 未采用：延续当前青眼深蓝造型

当前小青色方眼、正圆红头和深蓝圆底身体容易被读成机器人、钟表或胶囊，且不接近 Ringo 官方苹果吉祥物的视觉重点。

## 资产性质

这是在项目已证明的 Costume 载体中进行的**新表面专用重画**，不是对原版以撒玩家皮肤的锁定重绘，也不是把外部图片缩放或粘贴进图集。

- 坐标模板：现有三张项目自有 PNG 与三个 Costume ANM2。
- 语义参考：RingoTsuga 官方苹果吉祥物的苹果色、巨大浅色眼睛、短梗宽叶和浅色服装。
- 外部参考只控制造型词汇，不作为合成像素来源。
- 允许在每个已有裁切格内部重做可见轮廓；禁止跨格、改变枢轴、改变脚底接触点或改变方向含义。

## 三层视觉职责

### `head4`：身份轮廓

- 负责苹果最外轮廓、顶部凹口、果梗和宽叶。
- 正面苹果宽度略大于高度，但不能形成几何正圆。
- 左右两侧允许相差一像素，底部轻微收窄，形成手绘苹果感。
- 叶片为横向宽叶，不做细长尖角；果梗短且略倾斜。
- 正面/侧面开口必须与 `head2` 的红色内脸连续拼合，不形成双重粗边。
- 背面保留苹果红色体积和叶梗，不显示眼睛或泪痕。

### `head2`：官方脸部特征

- 红色内脸负责填满外壳开口并与外壳形成一个苹果，而不是第二个独立圆盘。
- 正面两只奶油色大眼占内脸宽度的主要部分；眼形略扁、左右可轻微不对称。
- 瞳孔使用深棕灰，尺寸小于眼白且允许一像素错位，避免机器人面板感。
- 嘴为二至四像素的小暗色开口，不使用青色矩形嘴。
- 青色只允许作为每侧一至两像素宽的短泪痕，不能成为大面积脸部主色。
- 侧面仅显示朝向镜头的一只大眼、相应小瞳孔和短泪痕。

### `body0`：浅色服装与比例

- 浅灰白上衣使用松软短上衣轮廓，不绘制兜帽、深蓝胸甲或圆形蓝底座。
- 领口藏在苹果头下方，只露出很小的暗色或阴影缝。
- 主体宽度明显小于苹果头；手脚小而深灰，避免身体与头部同宽。
- 正面可用一至两处浅色高光，背面不画正面领口。
- 移动相位只做一至两像素的上下起伏和脚步变化，不改变衣服整体体积。

## 锁定调色板

所有颜色均为不透明硬像素；透明色固定为 `RGBA(0,0,0,0)`。

| 苹果主体 | `#D96655` |

| 奶油色眼白 | `#F0E3CA` |
| 瞳孔/嘴 | `#30262A` |

| 叶片暗色 | `#345844` |

## 生成器与输出

继续使用：

- `tools/generate-ringotsuga-accessory-atlases.ps1`
- `Draw-AppleSilhouette`
- `Draw-FacePlane`
- `Draw-HoodieFrame`（函数名为兼容保留，职责改为浅灰白上衣）

生成器必须：

1. 在写像素时阻止越出画布；
2. 在保存前把所有透明像素归一化为零 RGB；
3. 生成三张原始尺寸 PNG；
4. 重新生成 `reports/ringotsuga_accessory_atlases_preview.png`；
5. 预览继续使用最近邻缩放，并按 `body -> face -> shell` 合成四方向首帧；
6. 额外在预览中保留原始游戏尺寸组合，防止只在放大视图中好看。

## 测试与验收

### 自动测试

先更新 `tests/ringotsuga_accessory_atlas_visual_test.ps1` 使旧图失败，再重画生成器并生成新图。

测试必须覆盖：

- 三张画布尺寸、RGBA 和现有格子映射不变；
- alpha 只能为 `0` 或 `255`；
- 透明像素 RGB 必须为零；
- 不含纯黑可见像素；
- 所有可见像素属于锁定调色板；
- `head4` 八格非空，`head2` 的 Up 两格为空且其余六格非空；
- `body0` 四方向各十格非空，其余格保持透明；
- 每个必需格的主体保持连续，不出现脱离主体的杂点；
- 苹果正面具有顶部凹口、底部收窄和宽叶，不能退化成正圆；
- 奶油色眼像素达到最低覆盖量，青色像素只占少量泪痕；
- 浅灰白衣服颜色达到最低覆盖量，旧海军蓝主体颜色为零；
- Right/Left 身体相位结构镜像；
- ANM2 裁切、枢轴、层名、Costume ID/优先级和 Lua 三槽位合同继续通过。

### 静态视觉审查

在原始游戏尺寸与最近邻放大尺寸分别检查：

- 第一眼是否能识别为 Ringo 苹果吉祥物；
- 是否不再像机器人、钟表、胶囊或圆形头盔；
- 大眼、宽叶、苹果凹口与浅色衣服是否在四方向一致；
- 头身比例是否为大苹果头配小身体，而非上下两个等宽圆块；
- 轮廓是否干净，周围是否没有黑红杂边或透明脏 RGB。

### 游戏内验证

静态测试通过不等于游戏内验证。接入后需要分别检查：

- Down、Right、Up、Left 的站立与连续移动；
- 射击、受伤、拾取与常见道具 Costume 覆盖时的层级；
- 千变万化重复切换、离开房间、继续游戏后的挂饰保持与清理；
- 角色周围是否出现脏像素、裁切、抖动或脚底漂移。

只有完成以上游戏内检查后，才能称为实际游戏观感通过。
