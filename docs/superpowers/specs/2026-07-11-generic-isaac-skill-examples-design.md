# 通用 Isaac 技能的真实示例证据设计

## 目标

将 `docs/skills` 中的通用《以撒：忏悔》Mod 开发技能改造成可在任意 Mod 仓库使用的技能：先发现当前项目的真实实现，再在项目不存在对应机制时转向官方 API 或受控 fixture。neverbrith 仅作为第一份校准样本，不能成为通用技能的隐式前置。

## 范围与边界

- 改造范围是 25 份通用 `isaac-*` 技能及其 eval；`isaac-neverbrith-dev`、`isaac-neverbrith-router`、`isaac-neverbrith-validator-profile` 保持项目专用，不被通用化。
- 不把 neverbrith 尚未实现的卡牌、挑战、角色、NPC/Boss、房间/关卡等内容伪装成真实范例。
- 不因为其他 Mod 的实现引入 EID、MCM、StageAPI、CuerLib、REPENTOGON 或其他第三方依赖；官方 API 与当前项目已声明的依赖优先。
- 不修改现有 Mod 玩法、资产、XML 或 Lua；本轮只完善技能、证据索引与技能评估。

## 统一证据协议

每份通用技能在其“First Move”阶段采用相同的三层选择顺序：

1. **当前项目真实锚点**：先扫描项目的 Lua、XML、资源与测试，记录可复查的 `路径 + 符号/节点 + 行号`。只把机制相同且生命周期兼容的代码当作先例。
2. **官方 API 路线**：当前项目没有对应实现时，使用该技能已带的官方 API/回调/注册参考；输出中明确写为“项目无例子”，而不是虚构一个本地模式。
3. **受控 fixture 路线**：当官方 API 还不足以说明组合边界（例如自定义角色、挑战、Boss AI、StageAPI 兼容）时，使用技能目录内的小型 fixture 和 eval。fixture 必须自包含，标明前置与故意省略的部分，不能被描述为真实项目代码。

所有技能的最终输出都应报告证据来源类别（`项目实例`、`官方 API`、`fixture`）和相应路径；无法确认时保留 `TBD`。

## 文档与数据组织

- 新增一个共享的“示例证据协议”参考文件，说明上述选择顺序、锚点格式和禁止伪造的规则。
- 新增 neverbrith 校准索引，逐项登记真实锚点与明确的“无本地实例”理由。它是开发/验证资料，不是通用技能运行时依赖。
- 每份通用技能只增加一段很短的发现指令，并链接共享协议；具体领域选择仍留在该技能已有 references 中，避免把 25 份技能复制成 25 套项目路径表。
- 新增或扩展 eval：覆盖“已有真实实例”、“项目没有实例但官方 API 足够”、“需要 fixture”三种输入。断言只检查证据选择、路径真实性、依赖边界与 `TBD` 行为，不要求模型照抄示例代码。

## neverbrith 校准原则

可复用的真实样本会优先来自 `main.lua` 中的回调、投射物、主动道具、状态持久化、EID、渲染和奖励逻辑，以及 `content/`、`resources/`、`tests/` 中与其配套的 XML、ANM2 和行为测试。示例引用必须由审计表逐条确认后写入索引。

没有可用样本的机制将明确标为以下其中之一：

- `官方 API`：技能可仅依赖官方文档/内置参考完成。
- `fixture`：需要最小可运行或静态可验证的合成样例。
- `项目未实现`：保留为未覆盖的校准空白，不用 fixture 伪装为项目实例。

## 验证与完成标准

1. 所有 25 份通用技能都指向统一证据协议，且未硬编码 neverbrith 作为依赖。
2. 校准索引中的每个“项目实例”都能由仓库内实际路径和行号复查。
3. 每个没有项目实例的技能都被归类为官方 API、fixture 或项目未实现，三者不得混淆。
4. 新增 eval 能阻止以下回归：编造本地文件、把可选库变成前置、把 fixture 宣称为真实 Mod 代码、在未知设计字段上填默认值。
5. 运行现有技能 eval 与发行前检查；报告静态结果与仍需游戏内验证的部分。

## 实施顺序

1. 收束独立审计，生成并人工复查 neverbrith 校准索引。
2. 加入共享证据协议，并以最小文本改造通用技能。
3. 为三类证据路线补齐 eval/fixture。
4. 运行静态与 eval 验证，检查打包产物不把 neverbrith 校准资料误当作通用运行时前置。
5. 汇总变更、证据覆盖和未覆盖机制。
