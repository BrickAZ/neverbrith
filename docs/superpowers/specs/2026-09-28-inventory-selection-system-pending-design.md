# 背包系统 — 待开发系统

记录日期：2026-09-28。

当前进展（2026-10-02）：**已接入，待实机验收**。用户随后授权开发并采用[补全合同](../../../reports/batch-completion/2026-10-02-proposed-contracts.md)中的调用者操作边界与交互规则。接口、调试入口和限制见[实现专题](../../agent/topics/pending-content.md)。下文保留 2026-09-28 的历史设计。

## 1. 用户确认的目标

用户原文：

> 背包系统是能够让玩家选择自己道具栏里面某一个道具进行某一个操作。

核心承诺：玩家能够从自己已持有的道具中选定一个目标，并对它执行当前功能所提供的操作。

系统定位为可复用的道具选择与操作入口。用户本次定义的是对现有道具栏中道具的选择能力，没有定义额外储存空间、容量、装备槽位或负重规则。

## 2. 功能拆分建议

以下用于后续细化，属于 **Suggestion — 待确认建议**，不代表所有交互已经定案。

1. 某个道具或功能请求一次“选择目标并操作”。
2. 背包界面展示当前玩家持有的道具，并说明本次操作是什么。
3. 玩家浏览并选定一个目标；界面应让玩家辨认当前选中项。
4. 玩家确认后，由调用功能对目标执行对应操作；取消则退出选择流程。

建议让背包系统负责展示、选择和传递结果，让调用功能负责目标资格、效果、费用和次数限制。这样不同功能可以复用同一个选择入口，不需要每个道具各做一套界面。

“选择一个道具”本身不意味着所有道具都能被所有操作作用。复制、移除或转换等仅是可能的接入例子，并非已批准的常驻操作菜单，也不等于玩家获得随时免费执行这些操作的能力。

## 3. 候选接入道具

[神的左手，恶魔之右手](2026-09-28-divine-left-hand-demonic-right-hand-pending-design.md)可作为后续讨论的接入例子：使用主动道具后，让玩家选择一个已持有道具作为临时复制目标。

**该接入尚未确认**。道具当前记录的规则仍是复制最后获得的道具；采用背包选择会改变该规则。系统成立不以此道具已经接入为前提，也不宣称现有道具已支持本系统。

## 4. 开发前待定边界

以下均为 **TBD — user decision required**，可以留待正式开发时讨论，不影响本次待开发归档。

- **入口与交互**：由哪个功能/按键打开，键盘与手柄如何选择、确认和取消，选择期间是否暂停游戏。它们决定实际操作流程。
- **道具展示与选择粒度**：主动/被动道具、临时道具的展示范围；同名多份按种类合并还是逐份选择；排序与目标识别方式。它们决定“一件道具”在界面中的具体含义。
- **操作与限制**：首批接入功能及操作种类、每种操作的合法目标、费用与失败处理；是否接入上述临时复制道具。不得由通用界面替调用功能决定玩法。
- **状态变化与归属**：选取期间换房/换层、失去目标、死亡复活及退出游戏时如何处理；合作模式下各玩家的界面和操作控制。它们决定中断与多玩家行为。

## 5. 后续开发验收方向

以下为待执行的验收方向，不代表界面或功能已验证。

- 展示当前玩家自己的实际持有道具，选择指向可辨认的目标。
- 确认后将正确目标交给本次操作，避免误作用于另一件道具或另一位玩家。
- 同名多份的选择含义与第 4 节最终决定一致。
- 无合法目标、目标在操作前发生变化或流程被中断时，按最终确认的失败规则处理。
- 自动检查应覆盖选择结果与操作调用；实际显示、输入、手柄操作、暂停及合作体验分别进行游戏内验收。

本系统与具体道具的玩法记录分别维护，通过链接建立接入关系；不得把候选操作或未确认的交互建议当作已实现功能。
