# Dante 眼睛保护与克制灵动头发设计

日期：2026-09-02  
项目：`E:\Isaac - Repentance\mods\neverbrith`

- **Locked：** 角色造型只能参考 CAPCOM《鬼泣5》标准 Dante。
- **Locked：** 禁止参考《鬼泣1—4》、动画、重制／重启、跨界、同人或其他版本。

- **Approved：** 正常移动头发继续使用独立 `512×64` Null Costume；不重新塞回 `512×512` 基础图的普通 `32×32` 头部格。
- **Approved：** 采用“眼睛优先的克制灵动”方向：先保证脸部可读，再加入与成年 Dante 气质相符的轻微步态起伏和发梢滞后。

## 2. 当前失败与根因

当前资源在尺寸、路径、ANM2、Alpha 和生命周期上静态有效，但原生合成遮住眼睛，因此状态必须记录为：

```text
technical: static pass
visual: failed — eye occlusion and rigid hair motion
in-game: not verified
user approval: rejected for revision
```

预览合成并未错误下移头发。官方基础头使用 `XPivot=16`、`YPivot=28`、`YPosition=-5`；头发 Costume 使用 `XPivot=32`、`YPivot=44`、`YPosition=-5`。预览按两者真实裁切原点差 `16,16` 合成，与 ANM2 坐标合同一致。

按当前基础头的深色脸部特征像素与头发 Alpha 相交测得：

| 帧 | 当前相交像素 |
| --- | ---: |
| Down A | 40 / 68 |
| Down B | 10 / 20 |
| Right A | 8 / 32 |
| Right B | 0 / 14 |
| Left A | 11 / 32 |
| Left B | 2 / 14 |

即使将整层头发统一上移 3 像素，Down A 仍有 22 个相交像素；统一上移还会破坏后脑、头顶、发梢与现有 Pivot 的关系。因此根因是刘海和侧发轮廓侵入脸部，不是全局位置偏移。

现有测试只要求宽泛脸窗 `x=24..40, y=25..43` 达到一定透明率。这个指标允许眼睛被遮住后仍由脸颊、下巴和嘴部周围的透明像素凑够比例，必须替换为逐帧的真实脸部保护掩码。

灵动性不足同样来自像素而非 ANM2：当前 A/B 轮廓重合率为 96%–100%，背面两帧轮廓完全相同，重心变化不足 0.16 像素。当前生成器还会给每块内部发片绘制封闭深边，配合大块竖直高光和齐直末端，形成金属甲片感。

## 4. 眼睛与脸部保护合同

### 4.1 掩码来源

从当前项目的 `character_dante.png` 六个官方正常基础头格读取真实 RGBA，按官方 ANM2 的方向和镜像关系映射到 `64×64` 合成坐标：

- Down A：基础头 `XCrop=0`；
- Down B：基础头 `XCrop=32`；
- Right A：基础头 `XCrop=64`；
- Right B：基础头 `XCrop=96`；
- Left A/B：使用 Right A/B 的基础头并按官方 `XScale=-100` 镜像；
- Up A/B：基础头 `XCrop=128/160`，没有正面眼睛保护要求，但仍保护头部锚点。

保护掩码必须由实际基础头像素与明确的眼睛、泪痕和嘴部区域共同确定；不得用整个大矩形的总体透明率替代。掩码坐标写入测试时要标明方向、基础格和镜像来源。

### 4.2 零遮挡规则

- Down A/B：两侧眼睛、泪痕与嘴部的保护像素上，头发 Alpha 必须为 0。
- Right A/B：可见侧眼、泪痕与嘴部的保护像素上，头发 Alpha 必须为 0。
- Left A/B：镜像后的可见侧眼、泪痕与嘴部保护像素上，头发 Alpha 必须为 0。
- 自动检查必须在失败时打印帧名、头发源坐标和被遮挡的基础脸坐标。
- 允许头发覆盖额头和少量外侧眉缘，但不能依赖说明文字才能辨认眼睛。
- 原生 `1×` 合成是最终脸部可读性权威；自动零相交只能防退化，不能证明发型好看。

## 5. 轮廓设计

### 5.1 Down A/B

- 保留《鬼泣5》Dante 的银白中长分层发和不规则偏分。
- 中央刘海经过两眼之间或眼睛外侧，不得垂直穿过眼球主体。
- 两侧长发沿脸部外轮廓落下；可以达到脸颊或下颌高度，但不能跨进眼睛掩码。
- 正面不能再形成左右近似对称的封闭 U 形帘子。
- A/B 中发冠保持同一身份，末端产生轻微滞后。

### 5.2 Right/Left A/B

- 左右方向继续独立绘制，不用镜像复用头发像素。
- 可见侧眼始终完整可读；前发从额头上方弯向鼻梁外侧或脸轮廓外侧。
- 后部发量向脑后和颈侧延伸，前发不得为了留眼睛而退化成整齐短发。
- 左右保留不同的分缝、后部体积和发束长度。

### 5.3 Up A/B

- 背面由重叠、收尖、长短不同的发束构成。
- A/B 必须有真实轮廓变化，不能只改变内部颜色。
- 使用深色内部发束分界，不使用透明竖沟槽，不露出头皮。

## 6. 克制灵动合同

- 主体发冠随 A/B 步态产生约 1–2 像素的稳定垂直起伏。
- 外侧长发、刘海末端和后发末端可以比发冠多产生约 1 像素的滞后或反向偏移。
- 动态来源是步态起伏和柔软末端，不是兔耳、夸张弹跳、旋转或大幅横摆。
- 方向间可按官方头部运动差异调整幅度，但不得产生随机抖动或锚点漂移。
- ANM2 的两帧、Delay、Pivot、Crop 和 YPosition 保持不变；只有新证据证明坐标合同错误时才允许另开设计变更。

Chusheng 只证明“两帧像素本身可以承担整体起伏与末端滞后”。最终 Dante 的发型轮廓、银灰色阶和动态气质仍只来自批准的《鬼泣5》方向。

## 7. 像素组织与生成器结构

生成器继续保持确定性，但将绘制职责拆开：

1. `outer silhouette`：每帧唯一、连续但有凹凸节奏的外轮廓；
2. `major masses`：无封闭深边的主发量填充；
3. `selective strand separators`：只在主要发束交界使用短暗线；
4. `broken highlights`：沿发流分布的短小、断续高光；
5. `tip corrections`：原生 `1×` 可读的收尖、缺口和长短错落；
6. `face mask gate`：输出前拒绝任何保护像素相交。

不得继续对每块内部多边形统一执行完整 `DrawPolygon` 封边。不得使用随机数、坐标取模噪点、大面积竖直白条或齐平矩形发梢。

## 8. 测试与证据

### 8.1 RED

先新增或修改测试，使当前资源因眼睛遮挡而失败。失败输出至少包括 Down A，并证明宽泛脸窗透明率不能替代真实眼睛保护。

### 8.2 GREEN

重绘后要求：

- 六个可见脸部帧的保护掩码相交数均为 0；
- 八帧保持非空、二值 Alpha、合法裁切和方向覆盖；
- Left/Right 独立；
- Up A/B 轮廓不再完全相同；
- A/B 存在稳定的主体起伏和末端变化；
- 不以颜色数量、填充率或哈希差异证明美术质量；这些指标只能作为空帧、异常密度和误复用报警。

### 8.3 必需视觉证据

- 原始透明 `512×64` 图集；
- 六个有脸方向帧的原生 `1×` 基础头合成；
- 八帧 `4×` 最近邻像素检查；
- 棋盘、纯白和代表性房间色背景；
- A/B 并排接触表，显示发冠位移与末端滞后；
- 可选的红色诊断叠层，只在测试证据中标出保护掩码和任何相交像素，不进入正式资源。

最终状态必须分开报告：技术静态、原生 `1×` 视觉、真实游戏内和用户批准。没有真实 Isaac 画面时不得声称 in-game verified；没有用户查看新版证据时不得声称 user-approved。

## 9. 失败处理

- 若保护掩码通过但原生 `1×` 仍看不清眼睛，视为视觉失败，继续重绘，不放宽掩码。
- 若整体上移能改善一帧却破坏其他方向，撤回全局位移，修正具体发束。
- 若为增加动态而导致脸部遮挡在 A/B 间闪烁，固定脸部安全边界，只让保护区外的发梢运动。
- 若静态测试通过但游戏内 Pivot 或 Costume 叠层不同，记录为静态通过／游戏内失败，不能用预览替代实机。
