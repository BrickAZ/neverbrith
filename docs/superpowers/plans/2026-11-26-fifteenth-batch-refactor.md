# 第十五批：阴的诅咒、七咒之戒、ACE 反作弊系统

用户授权以截图所列三件为本批范围。使用当前工作区冻结基线，保持玩法、池、品质、资源、存档字段与回调顺序。

## 职责与约束

- 阴的诅咒：原根入口保留，私有 state/queries/pedestals/acquisition/runtime 分别拥有保存、查询、首个 Q4 处理、获取确认和生命周期/原生免疫接入。
- 七咒之戒：原根入口保留，私有 state/inventory/world/rewards/runtime 分别拥有保存、库存/生命限制、诅咒/敌人/激活、补偿/交易和运行回调。正式受伤倍率查询继续以原名字发布，不依赖 TestAPI。
- ACE：原 features 入口保留，私有 state/queries/audit/combat/runtime 分别拥有每次安装的状态、事实查询、处罚、NPC 监控/结算和生命周期。300ms 帧预算、五秒时钟和第三次单击击杀处罚全部保持。
- ACE 的 Game 查询复用现有 world_queries，外层仍保留只接受 function 和 false→nil 的旧边界。其余共享候选按实际错误处理、参数和结算时刻保留差异，见[消费者清单](../../../reports/refactor-batch15/2026-11-26/consumer-inventory.md)。
- 所有绑定紧邻 handler；入口只负责创建私有实例、导出兼容 API 和原序安装。继续/新局/退出行为以冻结源码为准，不顺带补设计。

## 验证与交付

冻结旧/新行为检查、155 个函数提取对照、完整入口回调对照、35 个登记失败阶段与 15 个缺失模块反例、原生伤害/免疫/处罚对照、范围和资源哈希复核。实际命令、失败和未验证范围见[交付记录](../../../reports/refactor-batch15/2026-11-26/delivery.md)。

并行任务可能暂时注入原生探针或修改其他模块；本批原生旧/新使用同一冻结环境，只替换三件实现。工作区综合检查与冻结检查分别报告。检查器因模块清单过长触发 Windows 命令行长度限制，本批改用临时清单并运行包含长清单反例的入口自测。

本批不提交、推送或发布；本批完成不代表整轮全部道具、所有手感和包级验收完成。
