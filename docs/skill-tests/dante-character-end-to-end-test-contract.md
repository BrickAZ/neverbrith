# Dante 自定义角色端到端 Skill 测试合同

本文件是交给实现 Agent 的完整任务合同。读取本文件后，直接在当前
`neverbirth` 项目内执行；不要把它改写成另一份计划后就停止，也不要把合同中的
验收要求当成已经通过。

## 1. 任务目标

以用户随任务提供的但丁参考图为主要视觉锚点，并且只在《鬼泣5》官方素材范围内
补充必要的造型证据，在当前 Binding of Isaac: Repentance 模组中制作并注册一个
可选择、可进入游戏的独立新角色 `Dante`。

本任务同时验收：

- 项目发现与 Skill 路由；
- 外部角色到 Isaac 像素语言的视觉转译；
- 玩家角色所需美术表面的发现、生成、接入和一致性；
- 独立角色注册；
- 静态验证、原生 `1x` 视觉验收和可执行的游戏内验证；
- 对未知项目事实、用户决定和运行时证据的诚实处理。

这是角色美术与注册测试，不是但丁战斗系统测试。

## 2. 已锁定范围

### 2.1 视觉来源：《鬼泣5》限定

用户会把但丁参考图与本合同一起交给你。该附件是本次测试的**主要造型锚点**，
唯一批准的作品与版本范围是**《鬼泣5》官方但丁素材**。允许使用其他《鬼泣5》
官方素材补足附件没有展示清楚的侧面、背面、遮挡区域、衣物结构或同一标准造型的
细节，但必须同时满足：

- 素材确实来自《鬼泣5》游戏本体、CAPCOM 官方发布内容或可核验的《鬼泣5》官方
  宣传／设定素材；聚合站、百科、搜索预览和转载只能作为发现线索，不能单独证明
  官方来源；
- 补充素材只能解释附件所示的同一标准造型，不能用《鬼泣5》的替换配色、概念变体、
  未采用设计或其他服装覆盖附件已经锁定的外观；
- 每份补充素材都要在来源台账中记录“官方出处、用于补足的表面或细节、直接观察到的
  事实”；不能把推断写成素材事实；
- 当补充素材与附件可见内容冲突时，以附件中的可见造型为准；无法消解的冲突标记为
  **`TBD — user decision required`**，不得自行拼接多个版本。

绝对禁止参考、混入或据此补画：

- 《鬼泣1》《鬼泣2》《鬼泣3》《鬼泣4》中的但丁；
- 《鬼泣》动画中的但丁；
- 任何重制版、重启版、跨界作品、联动作品或其他作品版本中的但丁；
- 同人设计、二次创作、AI 再设计或参考模组中的但丁；
- 无法核验为《鬼泣5》官方素材的“通用但丁”图片或设计细节。

附件即使带有转载站水印，也仍是用户明确批准的主要造型锚点；水印、站点标识、背景
和转载页面内容本身不属于获准造型。除这项用户提供的附件外，新增补充素材必须能追溯
到上述《鬼泣5》官方来源范围。

附件主要造型锚点中已经确认的身份信号包括：

- 银白色中长发；
- 深红色长外套；
- 黑色内搭、长裤、手套和靴子形成的深色主体；
- 背后的长剑；
- 双枪；
- 冷静、自信、危险但不躁乱的整体气质。

不得复制参考图中的水印、背景、摄影光照、写实人体比例或无关文字。

附件没有完整展示的背面、严格侧面、衣物内部结构和遮挡区域，不能仅凭附件认定为
已知事实。应先查找可核验的《鬼泣5》官方补充素材；仍无直接证据时，可以在不改变
上述身份信号的前提下做保守、可撤销的 Isaac 化补全，但必须在最终报告中明确列出
补全内容及其证据等级，不得把推断描述成附件或官方素材事实。若某个隐藏结构会决定
最终图集或独立 Costume 的核心形态，并且无法安全补全，将它标记为
**`TBD — user decision required`**，说明影响，并在依赖该决定的不可逆编辑前停止。

### 2.2 武器边界

长剑和双枪只作为但丁的视觉身份与装饰资源：

- 可以在角色选择肖像、合作头像、菜单画面或其他适合的已发现表面中出现；
- 可以在不遮挡玩家方向、脸、脚底、攻击读向和拾取动作的前提下，作为静态或
  Costume 装饰出现；
- 是否进入某个游戏内表面，由真实模板、显示尺度和原生 `1x` 可读性决定；
- 不要求所有表面同时出现剑和双枪。

禁止实现：

- 枪械射击；
- 剑攻击；
- 武器切换；
- 自定义弹药、蓄力、连段或伤害；
- 武器专属输入；
- 因武器产生的新实体、Projectile、Laser、碰撞体或音效机制；
- 为了表现武器而改变普通 Isaac 攻击结算。

若现有项目代码因为角色注册自然需要最小的角色识别或基础装饰刷新逻辑，可以使用；
不得借此扩展成战斗机制。

### 2.3 角色机制基线

本测试不评价原创平衡设计。`Dante` 应保持普通 Isaac 的基础游玩方式：

- 不新增专属主动、被动、口袋物品、饰品、跟班或变身；
- 不新增起始物品；
- 不新增属性加成、伤害修改、生命机制或特殊攻击；
- 不新增解锁条件、成就、挑战或完成标记奖励；
- 不新增第三方 API 前置。

角色注册格式如果必须显式填写基础属性，优先沿用项目已验证的“普通 Isaac 等同”
惯例或官方模板事实。若当前项目与官方证据不能证明具体值，不得凭记忆填写；把所需
字段列为 **`TBD — user decision required`**，但继续完成不依赖这些值的发现和可撤销
美术工作。

## 3. 工作区与权限边界

- 只允许修改当前 `neverbirth` 项目。
- 不修改全局 Codex Skill、`skill-test`、参考模组或其他项目。
- 不提交、不推送、不上传 GitHub，除非用户随后明确要求。
- 当前工作树可能已有大量用户改动；不得还原、覆盖或整理与本任务无关的内容。
- 遇到同一文件中的现有改动时，先理解并与其共存。
- 第三方模组只能作为用户明确授权后的只读证据，不能成为运行依赖、默认布局或
  实现答案。
- 默认使用 Isaac 官方 Repentance API 和当前项目已存在的实现惯例。

## 4. 必须使用的 Skill 路线

先使用路由与项目发现能力确认实际任务表面，再使用最小必要组合。预期核心能力包括：

- `isaac-neverbrith-router`；
- `isaac-mod-context`；
- `isaac-visual-style-translation`；
- `isaac-character-art-surfaces`；
- `isaac-players-characters`；
- `isaac-anm2-visuals`；
- `isaac-reskins-resource-overrides`；
- `isaac-testing-debugging`；
- `isaac-validators`。

只有项目发现证明需要时，才增加本地化、回调、状态生命周期、架构或其他机制 Skill。
不要为了显得完整而加载所有 Isaac Skill，也不要让辅助 Skill 取代主问题所有者。

## 5. 第一阶段：只读项目发现

在第一次文件编辑或图片生成前，必须读取当前项目并输出简短的“发现项与实施路线”。

至少发现：

- 当前模组根与 `RegisterMod` 所有者；
- 启动/加载入口；
- 当前自定义玩家注册是否存在及其真实惯例；
- 玩家 XML、角色名、本地 ID 与运行时 PlayerType 的实际合同；
- 当前资源根；
- 官方或项目内可作为模板的玩家皮肤、ANM2、Costume 与菜单资源；
- 玩家基础皮肤、Null Costume、专用玩家 ANM2 或其他载体的可行路线；
- 当前项目已有的本地化方式；
- 当前测试与验证入口；
- 附件主要造型锚点，以及计划使用的每份《鬼泣5》官方补充素材的可核验出处、用途和
  与附件的一致性；
- 可能与新角色同名、同 ID、同资源路径或同 Costume 冲突的现有内容；
- 工作树中会与本任务接触的既有未提交改动。

发现结果必须明确区分：

- 已由项目或官方模板证明的事实；
- 用户在本合同中已经决定的内容；
- 直接来自附件的造型事实、直接来自《鬼泣5》官方补充素材的事实，以及仅为 Isaac 化
  补全的推断；
- 仅是建议的实现路线；
- **`TBD — user decision required`**；
- 只能通过游戏运行证明的事项。

禁止在发现前假设：

- `main.lua` 是唯一入口；
- 角色必须使用某个固定文件名或目录；
- 动画名为 `Idle`、`Walk` 或其他习惯名称；
- 角色本地 ID、PlayerType、Costume ID 或 XML 顺序；
- 某个参考模组或第三方库已经存在；
- 某张 PNG 的画布尺寸、裁切格或实际显示尺寸；
- 注册成功等于美术加载成功。

如果当前项目缺少注册独立角色所需的真实入口或官方模板，列出缺少的证据并停止在
发现报告；不得凭空搭建与项目无关的另一套模组结构。

## 6. 第二阶段：视觉转译合同

在生成最终像素前，建立共享身份特征账本，并为每个实际发现的角色表面建立独立行。

### 6.1 身份特征分级

至少区分：

- **必须保留：** 能让原生 `1x` 玩家轮廓被认作本次但丁的核心信号；
- **表面相关：** 只在肖像、菜单或有足够空间的表面保留的剑、枪、衣物结构；
- **该尺度省略：** 缩小后只会成为噪声、黑块或随机亮点的细节。

身份特征账本中的每条造型结论还必须标注来源等级：**附件直接可见**、
**《鬼泣5》官方补充素材直接可见**或**Isaac 化保守补全**。不得用被禁止版本的素材
填补任何方向、动作或表面。

不得预先规定所有表面必须同时出现银发、红外套、长剑和双枪。每个表面都必须解释：

- 它保留了哪个身份信号；
- 为什么该信号适合这个显示目的；
- 省略了什么；
- 原生 `1x` 下最大的可读性风险是什么。

### 6.2 Isaac 化原则

- 必须基于真实官方或项目模板编辑，而不是从空白方形画布生成写实小人。
- 画布和裁切格是坐标合同，不是要求主体填满的可见尺寸。
- 不得把参考图整体缩小后塞进玩家图集。
- 外部语义参考只能来自本合同批准的附件与可核验《鬼泣5》官方补充素材；不得借用
  《鬼泣1—4》、动画、重制／重启版、同人或其他作品版本来“修正”轮廓、服装、年龄感、
  发型或武器造型。
- 不得把一张“主插画”继续缩放成基础皮肤、肖像、合作头像和其他表面。
- 每种表面必须按自己的用途和原生显示尺度重新编码。
- 先建立轮廓、负空间和大色块，再增加头发、衣褶、武器和五官细节。
- 银发应改变可读轮廓，但不能自动变成封闭头套。
- 红色外套必须和最深描边、黑色内搭区分，不能坍缩成一整块暗色轮廓。
- 剑与枪不得遮挡玩家方向、脸部、脚底、拾取动作或攻击读向。
- 不得使用矩形底板、暗色背景块或无关阴影板增强主体对比。
- 有 Alpha 通道不等于背景正确透明；必须检查主体 Alpha 几何。
- 不得通过删除所有黑色或近黑色像素清理背景。
- 不得复制参考图水印。

### 6.3 载体选择

根据项目证据选择并说明：

- 哪些身份特征进入玩家基础皮肤；
- 银发、外套、剑或枪是否需要拆为独立 Null Costume；
- 是否真的需要专用玩家 ANM2；
- 哪些武器细节只属于较大肖像或菜单表面；
- 如何避免被普通道具 Costume 不合理遮挡；
- 如何保证非 Dante 玩家不会获得这些基础装饰。

不要因为参考模组采用过某条路线就照搬。选择必须来自当前项目和官方模板。

## 7. 第三阶段：资源制作与角色注册

发现与视觉合同成立后，完成真实文件编辑。

### 7.1 美术资源

- 制作所有由真实消费者证明为必需的角色表面。
- 覆盖真实模板要求的方向、动作、受伤、拾取、死亡或特殊帧；不要根据记忆虚构帧，
  也不要只画展示帧。
- 保留画布尺寸、像素密度、裁切矩形、帧顺序、Pivot、位置和脚底接触合同。
- 原创轮廓可以在所属裁切格内受控扩展，但不能跨格或整体漂移。
- 对没有真实消费者的“可能需要”资源，只列入建议，不要凭空注册。
- 生成或编辑后必须真实检查 PNG，而不是只凭生成提示词声称它符合尺寸与 Alpha。
- 每个原创或改绘身份细节必须能回指附件、来源台账中的《鬼泣5》官方素材，或明确
  标注为保守补全；不得出现来源不明的“通用但丁”细节。

### 7.2 角色注册

- 注册独立的新角色 `Dante`，不得覆盖或重命名任何原版玩家。
- 本地 XML 身份、运行时 PlayerType 和其他系统使用的身份必须分开处理。
- 运行时身份应通过当前项目和官方 API 支持的名称/注册查询方式获得，不得硬编码
  “原版最后一个 ID 之后”的全局数字。
- 本地 ID 必须唯一、稳定，并符合当前 XML 约定。
- 玩家资源路径必须来自实际创建并验证的文件。
- 不添加未请求的第三方前置。
- 若项目已有统一本地化方式，至少保证该角色名称在项目支持的中文和英文环境中不会
  因缺项导致空白、错误 token 或加载失败。

### 7.3 生命周期与多人

即使角色没有专属机制，也必须检查：

- 单人新开局；
- continue；
- 死亡与复活；
- 合作模式中 Dante 与非 Dante 玩家同时存在；
- 两名 Dante 同时存在；
- 中途加入（若当前项目和游戏入口支持）；
- reload；
- 换房、换层和重新开局；
- Costume 不重复叠加、不泄漏给其他玩家、不因重进流程消失或倍增。

没有实际运行证据时，只能把这些列为待游戏验证，不能声称已经通过。

## 8. 第四阶段：强制验证

### 8.1 自动与静态检查

运行项目中真实存在的相关检查，并报告准确命令和结果。验证面至少包括：

- XML 可解析；
- 本地 ID、名称和注册项无冲突；
- 所有新增资源引用存在；
- PNG 模式、尺寸和 Alpha 合法；
- ANM2 图集路径、裁切、帧和动画引用有效；
- 不透明像素没有越过所属裁切区域；
- 没有意外矩形底板、大面积低变化背景、孤立 Alpha 小岛或半透明杂边；
- 在有可信模板时检查 Pivot、脚底、中心和逐帧包围盒异常跳变；
- 不存在硬编码的 post-vanilla 全局 PlayerType；
- 来源台账中的所有外部语义参考均可核验为本合同批准的附件或《鬼泣5》官方素材，且
  没有列入任何被禁止版本；
- 无关既有测试没有因本任务回归。

自动检查只能证明文件和合同，不得声称它证明角色好看、像但丁或已在游戏里加载。

### 8.2 原生 `1x` 视觉证据

必须产出并实际查看：

- 原始透明资源或图集；
- 与对应官方/项目模板的叠加对比；
- 真实原生 `1x` 预览；
- `4x` 最近邻像素检查图；
- 浅灰棋盘、纯白和代表性房间/UI 背景合成；
- 动画、方向和状态接触表；
- 所有实际角色表面各按自己的原生显示尺度组成的总览板。

原生 `1x` 是比例、轮廓和识别度的视觉权威。`4x` 只用于检查像素工艺。

以下任一情况必须判定视觉失败并返工：

- 只像银发红衣的换色以撒，看不出稳定的但丁身份；
- 银发变成罩住整个头的封闭头套；
- 红外套与黑色主体、描边融合成实心暗块；
- 剑和枪在玩家帧里遮挡方向、脸、脚或动作；
- 不同方向、动作或菜单表面像不同角色；
- 只有放大图好看，原生 `1x` 无法辨认；
- 生成素材包含参考图背景、水印、矩形暗底或其他非主体内容；
- 造型明显借用了《鬼泣1—4》、动画、重制／重启版、同人设计或其他作品版本的独有
  特征；
- 使用了无法核验出处的补充素材，或者使用《鬼泣5》官方补充素材却没有在来源台账中
  记录其出处和用途；
- 补充素材覆盖、稀释或改写了附件所示的银白中长发、深红长外套和深色主体等主要
  造型信号；
- 技术检查通过，但各表面没有共同、可解释的身份语言。

### 8.3 游戏内验证

能够运行游戏时，至少验证：

- `Dante` 出现在正确的角色选择入口；
- 选择后能进入游戏且不崩溃；
- 角色名称和必要菜单资源不为空白；
- 游戏内基础皮肤、头发、外套和经批准的装饰显示在正确玩家上；
- 原版玩家与其他自定义玩家不受影响；
- 合作模式不会把 Dante 外观错误应用给其他玩家；
- 拾取普通道具 Costume 后，基础身份仍合理，且不会出现明显错误遮挡或重复叠层；
- continue、死亡/复活、reload、换房和换层没有身份或视觉残留；
- 剑和双枪没有产生任何未请求的战斗行为。

如果当前环境无法自动启动游戏或获得可信游戏画面，明确报告为
`in-game technical: blocked`，并给用户一份精确、可复现的手动测试步骤。不得把静态
通过写成“游戏内已通过”。

## 9. 状态报告合同

最终报告必须分别给出：

- **Implementation:** complete / partial / blocked；
- **Technical static:** passed / failed / blocked；
- **Visual native-1x:** passed provisionally / failed / blocked；
- **In-game technical:** passed / failed / blocked；
- **User visual approval:** passed / pending。

只有以下条件同时成立时，才能把整个任务称为完成：

- 独立角色注册和必要资源已实际写入当前项目；
- 静态检查真实通过；
- 原生 `1x` 视觉证据已实际查看并通过；
- 角色在游戏中真实加载和可选择；
- 用户批准最终游戏内视觉效果。

缺少最后两项时，可以把实现交付给用户测试，但不能声称“完整端到端通过”。

## 11. 禁止的错误完成路线

- 只写计划或提示词，不制作实际资源和角色注册。
- 没读项目就凭经验创建路径、XML、ANM2、动画名或数值。
- 复制另一个模组的角色注册和资源路径。
- 把现有角色改名成 Dante，而不是注册独立玩家。
- 硬编码“最后一个原版 PlayerType 加一”。
- 用一张生成图同时充当玩家皮肤、角色肖像和合作头像。
- 把参考图整体缩小后塞进玩家图集。
- 只生成正面展示图，不覆盖真实模板要求的其他方向和状态。
- 只检查 PNG 画布和 Alpha 通道，不检查实际 Alpha 几何与逐帧裁切。
- 只看 `4x` 放大图，不看原生 `1x`。
- 自动测试通过后直接宣称美术或游戏内通过。
- 因为参考图出现枪和剑，擅自实现任何战斗机制。
- 以“都是但丁”为由参考《鬼泣1—4》、动画、重制／重启版、同人设计或其他作品版本。
- 把无法追溯官方出处的聚合站图片、百科配图、搜索缩略图或转载图当作新的《鬼泣5》
  官方补充证据。
- 为了完成任务而回退、覆盖或清理用户已有的无关改动。
