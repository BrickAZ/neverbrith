# 本轮未进入生产的接口与实验

环境基线：普通 REPENTOGON 1.0.12a。用户已明确不是忏悔龙＋。没有安装或升级环境，没有启动游戏，没有执行进程内实验。这里记录边界，不是实验成功报告。

| 计划 | 本轮结论 | 后续最小条件 |
| --- | --- | --- |
| P2 肉块真复活 | 按用户新决策不执行，保留取消致命伤的现行行为 | 若以后另行改变玩法，再评估独占生命来源；不能静默删 c11 临时效果 |
| P3 有效伤害记账 | 不迁移，POST 不保证此刻已经发生非零生命损失 | 同版本游戏逐事件 PRE/POST/生命提交探针，尤其同帧取消＋有效、多次有效和盾 |
| P6 清房/付债 | 不以改缓存为名改写付债。脐带付债成功与否依赖真实伤害确认 | P3 证据明确后才处理债务扣除时机；确认实际清房及取消付债不会丢账 |
| P7 分组临时能力 | 当前版本缺计划需要的来源组合同，未迁移记忆紊乱 | 用户授权且实际环境支持分组 API 后核验数量/回调/存档语义 |
| P8 原生爆炸半径入口 | 当前无 MC_PRE_BOMB_DAMAGE；未建立同事件来源探针 | 先测自然/自有 Mulliboom 原生 source、damage、radius，不能按距离认领爆炸 |
| P9 XML 固定属性 | 不向旧版 XML 写入新版本属性字段，狗粮缓存保留 | 同版本字段和实际属性计算阶段等价证明 |
| P10a 阴的诅咒全覆盖禁防爆 | 未找到已验证的免疫单功能覆盖路线，现有代码未改 | 在当前版本先测试黑蜡烛免疫和护盾顺序，再对宿主帽/纵火狂逐项核验 |
| P10b ACE 低频更新 | 当前无计划所需 MC_PRE_UPDATE，不新增忙等或 CPU 工作负荷 | 独立且安全的更新控制与真实时间恢复证据；不能称 NPC 减速为真实低 FPS |
| P10c 七咒精确权重翻倍 | 未实施原生池权重探针，未修改 Q4 留底座＋额外补偿合同 | 固定种子、实际剩余权重、耗损、预览/抽取与沙漏恢复证据 |

神风本轮只修复可证明的身份、生成计时、追踪和安全爆炸调用失效。固定伤害 40 与 RadiusMult=2 是当前实现参数，不能当作已测量的原版伤害与真实两倍半径证明；外部致死路径的统一双倍范围仍未完成验证。

上述项目的“未执行/未验证”不阻塞独立的伤害金额表、原生充能和鸿运派生缓存；拾取来源优化本轮仍暂停，最终不会被合并写成“总计划全部完成”。
