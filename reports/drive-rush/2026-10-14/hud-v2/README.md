## 资源用途

| 项目 | 本版约定 |
| --- | --- |
| 主要用途 | 对应玩家生命 HUD 下方的斗气槽 |
| 载体 | 独立屏幕 UI Sprite 的 PNG 与 ANM2 资源；本次没有编写加载或渲染代码 |
| 槽体 | 每个裁切严格 60×8 px，100% 缩放，左上角为 (0,0) |
| 普通槽 | 六格，每格占宽 10 px，保留半格刻度；小数按像素显示 |
| 附属标记 | 箭头、暂停、警告、断裂、锁各 8×8；独立于槽体 |
| 力竭文字 | 独立 24×12 中文位图，带暗色描边；不计入 60×8；后续本地化可以由文字渲染替代 |
| 动画 | 30 FPS，所有根位置固定，不产生位移或玩法事件 |
| 适用边界 | 不替代角色蓝防／绿冲特效、道具图标、EID、死亡或收藏页资源 |

演示中的标记坐标相对槽体为：左标记 (-10,0)、右标记 (62,0)、力竭文字 (0,10)。完整附属显示会超出 60×8；60×8 严格指槽体。它们是局部资源排布，不是已通过游戏测试的生命 HUD 锚点。

## 已完成的表现

| 情况 | 表现 |
| --- | --- |
| 未力竭且 ≥3 格 | 绿色；恰好 3 格也绿色 |
| 未力竭且 <3 格 | 褐色；≤1 格另显示黄色警告 |
| 扣费 | 有效填充立即缩短；仅失去的区间出现暗红残留，6f 淡出 |
| 蓝防／击杀即时回气 | 仅新增区间亮起，6f 淡出 |
| 完美蓝防回满 | 整槽亮起 6f，最后保持满槽绿色 |
| 进入力竭 | 切换灰框灰白样式，槽内 `EMPTY` 闪两次；总计 18f（0.6 秒）的视觉提示 |
| 力竭恢复 | 连续灰白进度条，取消六格分隔；左侧断裂标记、下方“力竭” |
| 力竭恢复超过 3 格 | 继续保持灰白，直到实际回满并解除力竭 |
| 解除力竭 | 使用同一套 6f 满槽亮起，然后恢复六格绿色 |
| 离身冻结 | 灰白恢复进度保持原位，右侧锁标记 |

`EMPTY` 的闪烁时长只属于本版美术反馈，不增加无法操作时间。力竭自然回满 20 秒、有效行走额外加快 50% 等既定玩法规则没有变更。本次没有制作人物疲劳姿态或角色变灰动画。

《街霸 6》力竭的灰色状态与 `EMPTY` 提示参考[格斗游戏术语库 Burnout 说明](https://glossary.infil.net/?t=Burnout)；灰白恢复条在本项目中按 60×8 HUD 重新整理。没有直接提取或分发《街霸》的原游戏贴图。

## 文件与动画名

资源目录：`resources/gfx/UI/DriveGauge/v2/`。

| 文件 | 动画名／用途 |
| --- | --- |
| `drive_gauge.anm2` | `Full` 静态满槽；`GreenFill`、`BrownFill`、`BurnoutFill` 为 0～60 帧的数值查表，每帧表示 0.1 格 |
| `drive_gauge_feedback.anm2` | `Spend`、`Gain` 是透明反馈遮罩；`Refill` 是完整满槽反馈；`BurnoutEnter` 是空槽与 EMPTY 提示；`SpendExample`、`GainExample` 是可直接播放的 6f 合成示例 |
| `drive_gauge_icons.anm2` | `Walk`、`Pause`、`Warning`、`Broken`、`Lock`、`BurnoutLabel` |
| `drive_gauge_demo.anm2` | `Full`、`Walking`、`LowPaused`、`Critical`、`Burnout`、`BurnoutLocked`；循环动画 `Cost`、`Gain`、`PerfectRefill`、`BurnoutCycle` |
| `drive_gauge_atlas.png` | 480×208，204 个槽体或反馈裁切，每个 60×8 |
| `drive_gauge_icons.png` | 64×20，独立标记与中文文字 |
| `states/*.png` | 7 个独立 60×8 PNG：满槽、3 格、2.5 格、0.5 格、空槽、力竭空槽、力竭进度 |

`drive_gauge_demo.anm2` 默认播放 `Cost`，可以独立看扣费效果。`drive_gauge_feedback.anm2` 默认 `SpendExample`。循环演示会在下一轮回到示例初始值，这不是资源自动恢复斗气。

## 后续接入约定（本次未实现）

1. 先读取真实斗气与力竭状态选择绿色／褐色／力竭，再选择显示帧。不能通过显示帧反推玩法数值，也不能把四舍五入后的“3 格”用来决定颜色。譬如真实值 2.999 仍用褐色。
2. 填充轨道仅作查表使用。建议显示帧取不超过实际数值的 `floor(斗气 × 10)`，限制在 0～60；0.1 格是本版显示采样单位，不改变实际斗气精度。边框和分格遮挡的像素可能使相邻帧看起来一样。
3. 不要自动播放 `GreenFill`／`BrownFill`／`BurnoutFill` 来计时恢复。实际恢复仍由以后实现的玩法状态驱动。自然／行走回复不调用短闪动画。
4. `Spend` 的遮罩应只显示在旧值与新值之间；`Gain` 只显示新增区间。遮罩自身是整条宽度，未来调用者必须限定区间。6f 合成示例只覆盖 3.5→2.5、3→3.5，不代表其他扣费只能用这两个数值。
5. `Refill` 已包含满槽底图，显示时替代普通槽体即可。`BurnoutEnter` 已包含空的力竭槽体；18f 后应按当时真实进度恢复查表显示，不能将提示动画当作禁止恢复的玩法计时器。
6. 状态优先级、玩家归属、暂停／隐藏、离身冻结、换房／读档仍按[设计文档第18节](../../../../docs/superpowers/specs/2026-10-13-drive-parry-rush-active-item-design.md#18-斗气hud)。资源不会自行触发这些状态。
7. ANM2 没有事件，不发起扣费、回气或解除力竭；所有状态变化都需要未来玩法代码明确触发。
