# Design Authority

Use this rule whenever a task includes a mechanic choice, reward policy,
numeric value, pool/quality decision, restriction, visual direction, or
player-facing wording.

- An explicit user decision is locked. Do not replace, rebalance, reinterpret,
  or silently improve it.
- Use established conversation decisions, approved project contracts and
  explicit delegation first. Only a relevant user-owned choice still unresolved
  after that check is `TBD`; omission from the latest message does not reopen it.
  A proposal outside that authority is a labeled suggestion, not approved input.
- Do not turn a suggestion into Lua, XML, ANM2, or gameplay behavior without
  direct user approval or an explicitly approved project decision record.
- The agent may choose technical details that do not alter design intent:
  file placement, callback wiring, storage representation, formatting,
  validation, and test scaffolding.

Distinguish established decisions, unresolved choices and suggestions when
needed for the task. No separate approval table or repeated confirmation is
required. Do not invent numbers or restrictions to fill a template. Follow the
[shared execution and reporting policy](tbd-disclosure.md).
